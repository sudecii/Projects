# 📊 Credit Scoring Microservice

Полный ML-пайплайн + production-ready микросервис для оценки кредитного риска и принятия решений об одобрении кредита.

### 🎯 Бизнес-задача
Прогнозирование вероятности дефолта клиента (default_flg) для минимизации убытков банка при сохранении приемлемого уровня одобрений.  
Учитывается асимметрия ошибок: пропуск дефолтника (FN) в 10 раз дороже, чем ошибочный отказ хорошему клиенту (FP).

### 📂 Данные
Датасет Fintech Credit Scoring (Kaggle-style):  
- `application_info.csv` — признаки клиента (возраст, доход, BKI-скор, регион и др.)  
- `default_flg.csv` — целевая переменная (1 = дефолт)  
Объём: ~205k записей, разделение на train/val/test по полю `sample_cd`.

### 🛠️ Технологии и подход
- **Язык и библиотеки**: Python, Pandas, NumPy, Scikit-learn, LightGBM, Optuna  
- **Feature Engineering**:
  - Логарифм дохода (`income_log`)
  - Отношение дохода к рейтингу региона (`income_per_region_log`)
  - Возраст относительно отказов (`age_per_rejcnt`)
  - Временные признаки (`app_month`, `app_dayofweek`)
- **Модель**: LightGBM внутри sklearn-Pipeline с OneHotEncoding и Imputer  
- **Оптимизация**: Optuna (гиперпараметры)  
- **Основная метрика**: ROC-AUC = **0.73** на валидации

### 🎯 Подбор порога классификации
Учитывалась матрица стоимости ошибок (FN ×10, FP ×1).  
Оптимальный порог по минимизации ожидаемого убытка: **0.1054**  
- TPR ≈ 73% (ловим большинство дефолтов)  
- FPR ≈ 41% (trade-off)

### ⚡ Симуляция A/B-теста (off-policy evaluation)
На валидационной выборке (70k+ записей) сравнили две стратегии:

| Стратегия              | Порог   | Одобрено | Общий убыток | Средний убыток/клиент | Снижение убытков |
|------------------------|---------|----------|--------------|-----------------------|------------------|
| Baseline (простой)     | 0.25    | 94.1%    | 56 590       | 0.8008                | —                |
| Новая модель           | 0.1054  | 63.5%    | 23 510       | 0.3327                | **−58.5%**       |

→ Модель позволяет **снизить ожидаемые убытки от дефолтов почти в 2 раза** при умеренном сокращении одобрений.

### 🚀 Production-ready микросервис
- FastAPI-сервис принимает JSON с данными клиента  
- Автоматически генерирует признаки  
- Возвращает вероятность дефолта и решение (approve/reject)  
- Упакован в Docker (готов к деплою)
